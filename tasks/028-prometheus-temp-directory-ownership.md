# TB-028. Определить необходимость и cleanup Prometheus multiprocess directory

- **Статус:** done
- **Приоритет:** P3
- **Тип:** Технический долг

## Проблема и подтверждение

[setup_prometheus_multiproc_dir()](../temporal_boost/cli/prometheus.py) создаёт `mkdtemp()` при каждом многопроцессном запуске и меняет `os.environ`, но каталог не удаляется. Уже существующий путь проверяется только по `exists()`: файл вместо каталога тоже принимается. В самом пакете нет кода, который объединяет SDK metrics через этот directory.

После запусков остаются временные каталоги и изменённое окружение; настройка выглядит рабочим metrics-механизмом без подтверждённого потребителя.

## Что сделать

1. В рамках выбранной metrics-топологии определить реального потребителя `PROMETHEUS_MULTIPROC_DIR`; удалить автоматическую настройку, если она не нужна.
2. Если directory остаётся, валидировать тип пути и доступность, различать пользовательский и автоматически созданный каталог.
3. Привязать владение временным каталогом к родительскому process runner и очищать его после завершения детей, включая ошибку старта.
4. Восстанавливать изменённое окружение при программном вызове; не удалять пользовательский directory и его данные.

## Критерии приёмки

- [x] Повторный запуск не накапливает принадлежащие фреймворку временные каталоги.
- [x] При удалении directory API проверка файла вместо directory не применяется (см. результат).
- [x] Пользовательский каталог сохраняется после cleanup.
- [x] Документация не обещает агрегацию SDK metrics только за счёт env directory.

## Проверка

Добавить тесты с `tmp_path`, подменой окружения и отказом старта процесса. Проверить cleanup только собственных ресурсов без удаления пользовательских файлов.

## Результат выполнения

По топологии TB-011 SDK exporter не читает PROMETHEUS_MULTIPROC_DIR. Удалены модуль
cli/prometheus.py и вызов setup из process runner; временные каталоги больше не создаются,
os.environ не изменяется. Пользовательский Python prometheus_client, если нужен приложению,
полностью управляется приложением отдельно от SDK metrics.

Восемь параметризованных сценариев с tmp_path проверяют два последовательных запуска, unset env,
пользовательский directory с данными, обычный файл, отсутствующий путь и ошибку старта процесса.
Запрещён mkdtemp; проверяется точное сохранение environment, пользовательских файлов и дерева
путей. Все прошли в общей suite. Guide и ARCHITECTURE.md обновлены с описанием миграции.

Требование валидации файла вместо directory не применяется при выбранной альтернативе удаления:
CLI не использует этот путь и намеренно его не отклоняет. Если его потребляет другой компонент
приложения, проверка типа/доступности и cleanup принадлежат этому компоненту.

Проверки выполнены после реализации всей серии 020–028 по явному указанию пользователя.
Общие команды и итоги: [результат серии](README.md#проверка-серии-tb-020tb-028).
