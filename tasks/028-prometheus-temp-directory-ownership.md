# TB-028. Определить необходимость и cleanup Prometheus multiprocess directory

- **Статус:** backlog
- **Приоритет:** P3
- **Тип:** Технический долг

## Проблема и подтверждение

[setup_prometheus_multiproc_dir()](../temporal_boost/cli/prometheus.py) создаёт `mkdtemp()` при каждом многопроцессном запуске и меняет `os.environ`, но каталог не удаляется. Уже существующий путь проверяется только по `exists()`: файл вместо каталога тоже принимается. В самом пакете нет кода, который объединяет SDK metrics через этот directory.

После запусков остаются временные каталоги и изменённое окружение; настройка выглядит рабочим metrics-механизмом без подтверждённого потребителя.

## Что сделать

1. В рамках выбранной metrics-топологии определить реального потребителя `PROMETHEUS_MULTIPROC_DIR`; удалить автоматическую настройку, если она не нужна.
2. Если directory остаётся, валидировать тип пути и доступность, различать пользовательский и автоматически созданный каталог.
3. Привязать владение временным каталогом к родительскому process runner и очищать его после завершения детей, включая ошибку старта.
4. Восстанавливать изменённое окружение при программном вызове; не удалять пользовательский directory и его данные.

## Критерии приёмки

- [ ] Повторный запуск не накапливает принадлежащие фреймворку временные каталоги.
- [ ] Путь к файлу вместо directory отклоняется понятным образом.
- [ ] Пользовательский каталог сохраняется после cleanup.
- [ ] Документация не обещает агрегацию SDK metrics только за счёт env directory.

## Проверка

Добавить тесты с `tmp_path`, подменой окружения и отказом старта процесса. Проверить cleanup только собственных ресурсов без удаления пользовательских файлов.
