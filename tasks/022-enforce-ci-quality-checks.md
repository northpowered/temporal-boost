# TB-022. Сделать проверки типов и примеров обязательными в CI

- **Статус:** backlog
- **Приоритет:** P2
- **Тип:** Технический долг

## Проблема и подтверждение

В [ci_prepare.yml](../.github/workflows/ci_prepare.yml) mypy, Ruff/format для examples, проверка импортов и компиляция примеров завершаются с `|| true`. CI может быть зелёным после фактической ошибки этих шагов. Ruff настроен с `fix=true`/`unsafe-fixes=true`, поэтому обычный `ruff check` способен исправлять файлы в CI вместо независимой проверки.

Публичные примеры и типизация могут регрессировать без блокировки pull request.

## Что сделать

1. Собрать текущие ошибки и исправить их либо выделить конкретные временные исключения с причиной.
2. Убрать безусловное подавление exit codes у обязательных проверок.
3. Использовать `ruff check --no-fix` в CI и исключить изменение проверяемых файлов.
4. Обеспечить правильные extras и группы зависимостей для проверок примеров.
5. Добавить проверку строгой сборки документации на PR, если она остаётся только в deployment workflow.

## Критерии приёмки

- [ ] Ошибка mypy или поддерживаемого примера делает соответствующий job красным.
- [ ] Ruff в CI не модифицирует исходники.
- [ ] Обязательные checks не содержат безусловного `|| true`; исключения локальны и объяснены.
- [ ] Документация проверяется до merge, без публикации сайта из PR.

## Проверка

Запустить те же команды локально. Проверить поведение workflow на намеренно ошибочном fixture/временной ветке без публикации; удалить искусственную ошибку после проверки.
