# TB-027. Сделать приоритет автоматического ASGI backend явным

- **Статус:** done
- **Приоритет:** P3
- **Тип:** Доработка

## Проблема и подтверждение

В [get_asgi_worker_class()](../temporal_boost/workers/asgi_registry.py) Uvicorn выбирается явно, а остальные backend — по порядку ключей реестра. Порядок Granian/Hypercorn сейчас определяется импортами в [workers/__init__.py](../temporal_boost/workers/__init__.py), поэтому безобидная перестановка импортов меняет выбор сервера.

Одинаковый набор extras может получить другой backend после внутреннего рефакторинга.

## Что сделать

1. Определить явный порядок поддерживаемых backend, сохранив текущий фактический приоритет либо отдельно описав изменение.
2. Отделить priority built-in реализаций от порядка регистрации.
3. Определить fallback для пользовательских backend и поведение повторной регистрации ключа.
4. Документировать выбранный порядок и проверку доступности optional dependencies.

## Критерии приёмки

- [x] Перестановка импортов встроенных адаптеров не меняет результат `auto`.
- [x] Проверены все комбинации доступных built-in backend и отсутствие серверов.
- [x] Явный выбор backend не зависит от `auto` priority.
- [x] Пользовательская регистрация имеет определённое поведение без скрытой замены built-in.

## Результат выполнения

Явный ASGI_AUTO_PRIORITY сохраняет фактический исторический порядок: Uvicorn → Granian → Hypercorn.
Порядок регистрации/импортов не влияет на auto. Custom backends выбираются после built-ins по
лексикографически минимальному ключу. Повторная регистрация того же class/key идемпотентна;
другой class под существующим ключом вызывает ValueError, включая built-in keys. Регистрация
по-прежнему требует успешного импорта optional packages.

Параметризованные тесты покрывают все 15 порядков непустых подмножеств built-ins, пустой registry,
явный выбор каждого backend, custom fallback/приоритет built-in, duplicate registration и отсутствие
optional dependencies. Все прошли в общем unit-прогоне; registry имеет 100% coverage.
Правила описаны в API reference и creation guide.

Проверки выполнены после реализации всей серии 020–028 по явному указанию пользователя.
Общие команды и итоги: [результат серии](README.md#проверка-серии-tb-020tb-028).
