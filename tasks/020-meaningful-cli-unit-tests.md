# TB-020. Устранить ложноположительные тесты BoostApp.run

- **Статус:** done
- **Приоритет:** P2
- **Тип:** Тесты

## Проблема и подтверждение

В [test_boost_app.py](../tests/test_boost_app.py) два метода называются `test_run_with_args`; первый перезаписывается Python и не собирается pytest. Оставшийся тест подменяет `__call__` на instance Typer, ловит практически любую ошибку и допускает успех по условию `mock_run.called or len(app.get_registered_workers()) == 1`. Последняя часть не доказывает запуск команды.

Suite остаётся зелёной при ошибочном вызове CLI; регрессии аргументов и exit codes не обнаруживаются.

## Что сделать

1. Разнести сценарии по уникальным именам и удалить проверки, истинные независимо от поведения CLI.
2. Проверять Typer через `CliRunner` либо вызывать `BoostApp.run()` с корректным списком аргументов и наблюдаемым callback.
3. Убрать широкое подавление исключений из тестов; проверять конкретный ожидаемый результат.
4. Покрыть внутренний CLI и фактический синтаксис внешней entry point; для process selection использовать doubles.

## Критерии приёмки

- [x] Оба исходных сценария действительно собираются pytest как разные тесты.
- [x] Выбор worker приводит к вызову именно его `run()`; неверный выбор это не делает.
- [x] Тест падает при поломке маршрутизации или передачи arguments.
- [x] Зафиксирован синтаксис внешнего CLI без зависимости от неочевидного сворачивания команды Typer.

## Проверка

`uv run pytest tests/test_boost_app.py --collect-only` и запуск CLI-тестов. Дополнительно проверить, что искусственно неверная команда вызывает ожидаемую ошибку теста, а не ложный pass.

## Результат выполнения

Основные ложноположительные сценарии уже заменены в TB-008 уникальными тестами
`test_run_with_argument_list_dispatches_selected_worker` и `test_run_without_arguments_uses_sys_argv`.
Добавлен негативный сценарий: неизвестный worker даёт exit 2 и не запускает зарегистрированный callback.
Внешний entry point и programmatic argv проверены общей CLI suite с process doubles.

`uv run --offline --no-sync pytest tests/test_boost_app.py --collect-only -q`: **98 тестов**, оба
исходных сценария и новый негативный сценарий присутствуют. Дополнительная mutation-проверка через
временный mock `BoostApp.run -> SystemExit(0)` подтвердила, что тест dispatch падает при отсутствии
вызова выбранного worker; исходники при проверке не менялись.

Проверки выполнены после реализации всей серии 020–028 по явному указанию пользователя.
